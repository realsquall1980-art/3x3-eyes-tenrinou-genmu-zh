# 验收口径与证据（v1.1）

下面每一句都能在本机交付记录里复核；做不到的地方也照实写，不写成"已验证"。

## 1. 补丁格式：第三方工具实打

生成器按 Flips（Alcaro/Flips，ROM 补丁圈的事实标准实现，`libups.cpp`）的读法写；验证**不是**自写脚本自证，而是用编译出来的第三方 `flips` 真打：

| 碟 | 补丁大小 | `flips` 判定 | 输出 SHA-256 vs 本机构建 |
|---|---|---|---|
| Disc 1 | 234,993,256 B | `The patch was applied successfully!` | **完全相同** |
| Disc 2 | 331,089,513 B | `The patch was applied successfully!` | **完全相同** |
| Disc 3 | 372,847,304 B | `The patch was applied successfully!` | **完全相同** |

反面测试：Disc 1 的补丁打到 Disc 2 的日版 Track 1 上 → `This patch is not intended for this ROM.`，不产出文件。

### 为什么补丁这么大（224 / 316 / 356 MiB）

改动面本身很小，但 UPS 按"差异段"编码：本作的文本块与字库块散布在整盘各处，字幕层又是整帧重编码过的数据，导致差异段多、补丁体积接近原盘。这是本作固有的性质，不是打包错误——补丁里不含可运行镜像，仍需自备日版原盘。

> 附：更早下架的内部补丁只有 100–170 KB，看着"很干净"，那是因为它们的编码不符合 UPS 规范、常规工具一律装不上。**体积小不是优点。**

## 2. 这一版改了什么（相对上一版）

三碟整盘比对：**只差 12 字节**，全部落在两条菜单记录内。构建时带结构断言，不合规不写盘：

| 断言 | 结果 |
|---|---|
| 字段长度 8 字节不变 | 通过 |
| 终止符仍在字节 6–7 | 通过 |
| 零码个数与改前相同（1 个） | 通过 |
| 非零码多重集与改前相同 | 通过 |

## 3. 屏幕回归（四屏逐像素）

| 屏 | 比对 |
|---|---|
| 所在地说明正文 | Δ = 0 |
| 标题画面 | Δ = 0（仅末行与署名按设计改动） |
| 存档屏槽位与说明栏 | Δ = 0 |
| 六行菜单字 | Δ = 0（861 个字、3173 个白像素，与上一版同值） |

菜单实测字心：存档／读取 `123 / 195`（块中心 159），选项 `135 / 183`，人物介绍 `135 / 151 / 167 / 183`，所在地说明 `111 / 135 / 159 / 183 / 207`，返回 `135 / 183` —— 六行块中心一致。

## 4. 掌上设备的 CHD

Disc 1 制成 CHD（335,156,580 B），`chdman verify` 通过，`extractcd` 回抽与原盘成品逐字节一致；上传掌机存储后再拉回，SHA-256 与本地相同。

## 5. 明确的边界（不许当成"已验证"）

- **Disc 2 / Disc 3 未做逐屏实拍**：只做了盘内断言、补丁校验与 CHD 校验。
- **本版还没有真机回报**：屏幕证据来自 PCSX-ReARMed（与掌机前端同款内核）无头回放；Disc 1 已放进掌上设备，但用户侧回报未到。
- **存档槽缩略图未取得屏幕证据**：槽位方框确实读记忆卡数据，但验证用的存档是在黑屏时存的，卡内 768 字节缩略图区全 0。下一版用明亮场景存档重新取证。
- **选项页 `AUDIO / BGM / VOICE / メッセージ表示 / 非表示` 仍是原文**：盘上图片字，不是文本，本版未改。
- **「三只眼变身」图文精选整节仍是日文**：同为图片字。
- **ePSXe / VGS 未测**。
